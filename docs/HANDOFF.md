## 1. 最近做過什麼、為什麼（含今天被推翻或修正的決定）

### 1.1 v1.77.0：放棄長輩路線（線上就是這一版）
- **起因**：Yolin 原話（逐字，經轉達者）「另外無障礙的部分可以減掉了，當初設計上重點是給長輩，但這段期間發現長輩還是不會用，因此放棄長輩那條路，優化到年輕人會喜歡的介面」。
- **為什麼拆成 (甲)(乙) 兩堆**（轉達者的拆法，見 §2.3 可推翻）：「無障礙」裡混了兩種東西。
  - **(甲) 為長輩做的**——特大字、高對比、被長輩綁住的兩個 16px 字級下限：照 Yolin 的話拿掉。舊版存了特大字的人自動對應成「大」，存了高對比的人那個設定會被丟掉，只動顯示偏好、不碰行程資料。
  - **(乙) 任何人都需要的可用性底線**——文字對比 4.5、觸控 44px：**建議保留、由 Yolin 決定，他回覆之前維持現狀**。理由：這兩條不是為長輩訂的，拿掉會讓所有人變難用；「先拆再問」拆了就很難說回來。之後要放寬也是「改門檻並寫明理由」，**不是把測試拿掉**。
- **有意沒拿掉的**（我的判斷，可推翻）：標準字級 118% 是照長輩訂的，但它是整套字級、一改動到每一頁版面，而 Yolin 說「版面只改一次」，所以留到七項樣式那一輪一起定；程式裡十幾處「為長輩簡化的流程」拿掉等於改流程，是改版設計、不是刪除，留給改版。
- **(乙) 的數字對照**：靜態從 `css/style.css` 算過（390px 寬、沒在瀏覽器量），寫在 STATUS「16:4x Yolin 放棄長輩路線」那一節；結論是 36 對 44 的差別多半不到一列任務。

### 1.2 densitytest 門檻 700 → 720（為什麼不是「看到不合格就放寬」）
- **舊門檻 700 是在測試沒量到真正最壞情況時訂的**：句庫裡一直有一句帶時段標記的長句（夜市那種），舊測試用隨機種子抽句、又把帶時段的句子篩掉，**從來抽不到它**——所以舊的 700 從來不代表最壞情況。
- **處理順序**（這個順序才是重點）：
  1. **C**：先把測試改成「固定最壞情況」——直接讀句庫、帶時段的句子全部納進候選，不再靠隨機。
  2. **A**：先試著改版面（`.qline-head` 內距 8→7、`.qline-sub` 行高 1.35），省下 34px。
  3. A 之後最壞情況實測 702（門檻 700）、收合列 143（門檻 136），**仍然不過**。這時才列四個選項（不含帶時段句子／重訂門檻／改版面不折行／再縮留白）各附代價，**交給 Yolin**。
  4. Yolin 選 (b)：一個景點 <720、收合列 ≤150。
- **已知且刻意接受的代價**：兩條會一直標「⚠ 貼近門檻」（餘裕 18px／2.5%、7px／4.7%）。**不要為了消掉警告再放寬**；數字再長，該檢討的是版面。另外少了一道重疊守備（一般字級的「收合列最高」目前沒有突變弄得紅它），補守備的突變＝待辦 (8)，轉達者說等 Yolin 回報使用狀況再做。
- 理由也寫在 `scripts/densitytest.mjs` 檔頭「2026-11-12 Yolin 選 (b)」那段。

### 1.3 吉祥物：為什麼撤掉第 3 版，現在是第 5 版
- **方向**：10-27 定的「不擬人、原創圖形就兩個」**不再適用**——Yolin 11-12 指定六隻擬人化吉祥物（小白兔、白熊、白雪納瑞、長尾山雀、灰鷹、玄鳳），白色雪納瑞是主角但「大家都平等」，名字不重要，要白邊。
- **第 1 版**：為了避嫌拿掉兔子的粉紅內耳 → Yolin：「已經過度了」。**判準改成**：把名字拿掉，會不會被認成某一隻有名字的特定角色；**物種本來就長那樣的特徵照畫**。
- **第 2 版**：Yolin（逐字）「是可愛但不夠可愛，現在比較像是由不同形狀的幾何圖拼起來的」，附了一張參考圖（一隻有版權的兔子角色）。轉達者判斷是技法問題、不是題材問題。
- **第 3 版（撤回）**：把參考兔子量到的約 10 個比例直接當成參數 → **等於照牠的比例重畫一隻有版權的特定角色**（轉達者指出）。整版撤回。**之後的規矩**：
  - 參考角色量到的數字不准當參數、不准對著調、不出現在提案頁、不跟我們的數字並排。原始數字只留在本機 `.logs/`（被 .gitignore 擋掉），**永不進 repo**。
  - 第 3 版的 STATUS 曾有一張並排表，雖然下一個 commit 撤掉了，但推上去會永久留在公開歷史 → 推送前把本機三個 STATUS commit 合併掉（轉達者同意）。教訓：**撤掉內容不等於撤掉歷史，推送前要掃整段還沒推的 commit**。
  - 舊的提案頁連結的版本紀錄裡還有第 3 版 → 換了新連結（轉達者：「在不確定的時候，清掉比查清楚便宜」）。舊的那個 Artifact 工作階段刪不掉，要 Yolin 自己刪（§3）。
  - 不要替兔子加探險帽或背包（那是參考兔子的配件）。
- **第 4 版**：只跟我們自己的第 2 版比，從缺點歸納五條通則重畫 → Yolin「方向對」。
- **第 5 版**（現在等 Yolin）：只改鬍鬍（雪納瑞）。牠被說「像老人」，轉達者要求**正面解、不要默默接受**：把老人感拆成眉、鬍子、頰線、嘴四個零件，各換畫法，雪納瑞的招牌都留。其餘五隻跟第 4 版逐字相同。
- **雨衣維持黃色**（轉達者 21:2x 定）：黃色是雨衣的原型色，跟參考兔子的黃帽接近也不改——為了「不一樣」而換色就是過度規避。**揭露而不改**：照實寫在原創檢查裡。
- 提案頁是**私人 Artifact、不進 repo**；本機那份在 Session 暫存區（Session 消失就沒了；連結在轉達者手上）。

### 1.4 今天修的四支工具（都只在本機，見 §4.1 的「看起來正常的失敗」）
- `tools/ev/find-runall.mjs`：停程序工具原本會認到並殺掉呼叫它的 shell。轉達者：「修，不要只加警告」（殺錯是不可逆的）。

## 4. 只有做過的人才知道的陷阱

### 4.1 六件「看起來正常」的失敗（2026-11-12；細節在 STATUS「候選通則」一節）
輸出都長得跟正常時一樣，沒有一件是靠「測試紅了」被發現的：
1. **執行器印的字比它做的檢查多**：`mutate.mjs` 從 2026-10-02 到 11-12 的「N/M 條照預期紅」只數結束碼與項數、從沒比過 expect。**那段期間的「照預期紅」紀錄只證明紅了**；紅在哪幾行，要看那筆紀錄有沒有寫逐條對過。`tools/mutproof/` 的驅動不在此列。
2. **自查擋了、後面照樣往下走**：自查與 commit 用「;」接，命中也不停。**擋的那一步跟被擋的那一步之間只准用 `&&`**。
3. **取樣器把自己算進「系統」**（已修，見 §1.4）。
4. **停程序工具會殺掉呼叫它的 shell**：命令列「只是字串提到」目標腳本的指令也會被認成目標（已修）。凡是查程序表的工具，先排除自己與整條上層鏈。
5. **資源紀錄被下一場整份蓋掉**（已修）：檔案一直在，只是永遠只有最後一場。
6. **自查把正則誤判成路徑**：比對時間的正則（兩個「反斜線 d」相連接冒號）會被五類自查當成磁碟代號路徑。**改觸發的那一側**（時間寫成 `\d{2}`），不要放寬檢查器。寫進文件也用描述，原樣寫進來那一行自己會被擋。

### 4.2 推版要預留約一小時機器
- 待推範圍動到 `tools/ev/`、`tools/sample-run.mjs`、`scripts/affected.mjs`，`test:affected` 判斷不出範圍 → 放大成**全套 86 支、約 49 分鐘、會開瀏覽器**＝重負載。所以下一次推版的機器成本固定約一小時，跟改了多少無關。推之前先要到機器、先查機器時鐘（`date`），不要信別人轉述的「重置了」。

### 4.3 `safe-push` 的行為（`scripts/safe-push.sh`）
- **只能用它推，不要自己 `git push`**；指令後面**不要接管線**（`| tail` 會吞掉失敗）。
- 回傳值：0 推完且遠端＝本機；1 自查有命中；4 自查的檢查器壞了；2 push 失敗；3 推了但遠端沒更新；5 推送閘本身沒驗過；6 F8 的驗法沒驗過；7 HEAD 不在 main 上（或自查後 HEAD 又動了）。
- **推的是當下 checkout 的 HEAD、寫成遠端的 main**。所以 main 上有什麼就推什麼——不想推的東西不要放進 main。
- **新 clone、或動過推送閘那四支（safe-push.sh、prepush-scan.mjs、pushgatetest.mjs、verified-reg.mjs）**：commit 之後先跑 `npm run pushgatetest`，否則回 5。動到 build-places.mjs／importshots.mjs／f8verify.mjs／verified-reg.mjs：先跑 `npm run f8verify`，否則回 6。登記檔在 `.logs/`，不進版控，新 clone 沒有。
- 自查掃「遠端還沒有的**每一個** commit」，含 commit 訊息與作者欄；範圍照遠端實際狀態算。
- 推完讀線上 `sw.js` 的 VERSION 確認（11-05～11-11 這台曾連不到 github.io，11-12 起又連得到；連不到不代表線上掛了）。
- **撤掉內容不等於撤掉歷史**：推送前把還沒推的整段 commit 掃過一遍（訊息、增刪行、整檔）；有不該公開的，先合併本機歷史再推。

### 4.4 備份分支
- `pre-squash-1112`、`post-squash-1112`：18:2x 合併本機歷史前後的備份，**只在本機**。等 Yolin 實際用過 v1.77.0 確認沒問題才刪；刪了要記下來。

### 4.5 貼著門檻的測試（不要為了消掉 ⚠ 去放寬）
- 每條有數字門檻的斷言都會印「門檻、餘裕（%）」，餘裕 <10% 標「⚠ 貼近門檻」（`scripts/margin.mjs`）。**最新的清單看測試輸出裡的 ⚠**。
- 長期貼近、刻意接受的：densitytest「一個景點」702 對 <720、「收合列最高」143 對 ≤150；大字那節收合列 158 對 ≤170。
- 11-12 清晨盤過一份 12 條的清單（多數是 46px 對 ≥44 的按鈕：tagtest 任務卡與任務列、albumtest 相簿切換鈕、walltest 排序鈕等），在 STATUS「守夜第二段」。**那份之後部分過期**：v1.77.0 拿掉了特大字的幾條、字級下限改 13、行程頁那顆按鈕加到 50。
- 改樣式時這些最先紅；紅了先查是不是版面真的變長了。

### 4.6 其他
- **🔴 `npm run sweep` 會寫入正式站**，只有 Yolin 明確許可才跑——不是每版流程。
- **動到 `js/merge.js` 或 `workers/`：Worker 先部署、客戶端後推**（反過來會造成永久分歧）；部署前先 `wrangler whoami` 確認憑證，不要等到推的那一刻。
- **D1 的家人群組絕不刪、不改**；不寫 D1。
- 中文 commit 訊息寫進檔案再 `git commit -F`；中文 patch 腳本也寫進檔案再跑（Windows 的 heredoc 會走樣）。改檔一律用編輯工具，不用 shell 的 heredoc、`sed -i`。
- `git add` 逐路徑加，不用 `-A`／`.`。commit 前先跑自查，跟 commit 用 `&&` 接。
- Windows PowerShell 5.1 讀沒有 BOM 的 `.ps1` 會當成本機碼頁：`tools/*.ps1` 的程式碼保持 ASCII，中文只放註解。
- 新加的測試要登記進 `package.json` 的 test:chain（孤兒檢查會抓），STATUS「## 測試」的「完整的鏈 N 支」要跟著改（affectedtest T15 會抓）。
- 金鑰、真實 email、本機路徑、家人的名字與具體行程日期、Artifact 連結、參考角色的量測數字都不進 repo（共用慣例 §2.4 與附錄 A）。

## 5. 轉達者叫不動時：獨自接手的行為準則

**先假設**：沒有人會即時回你。Yolin 若直接在對話裡跟你說話，他就是決定者（他是轉達者的上游）；照樣用純文字列選項＋建議、停下來等，**不用互動式提示框**。

### 5.1 開工先確認狀態（都是唯讀）
- `git status --porcelain`（應該是空的）、`git rev-list --count origin/main..HEAD`（2026-11-12 收工時是 14）。
- `git ls-remote origin refs/heads/main`（問遠端本身，不信本機追蹤分支；收工時是 `b1dea99`）。
- 讀線上 `https://yolin0513.github.io/tripquest/sw.js` 的 VERSION（收工時 `tripquest-v1.77.0`）。
- `git branch --list` 看備份分支還在不在；`date` 看機器時鐘。

### 5.2 可以自己做的（可逆、本機、不吃機器）
- 讀任何檔案；在本機改程式、測試、工具、文件。
- 跑秒級檢查與常規測試（**這一次**預估不到 600 秒、不開瀏覽器）；跑之前用 `npm run affected`（只列不跑）看挑到哪幾支、預估多久。
- 本機 commit（逐路徑 add、自查 `&&` commit）；改寫**還沒推**的本機歷史（先開備份分支）。
- 做使用者看得到的改動（例如七項樣式）——**只在本機做，不推**；做完寫進 STATUS 等 Yolin 看。
- 更新 STATUS（每一輪結束前寫，Session 可能隨時斷）。

### 5.3 一定要停下來等 Yolin 的
- **推送**：任何 push，包括透過 `safe-push.sh`。拿不到許可就不推——**延後推送是可逆的，推一個沒驗過的版本不是**。
- **重負載**：開瀏覽器、這一次預估超過 600 秒、或 2 個以上工作程序且超過 60 秒。沒有轉達者時，你看不到別的專案正在跑什麼，所以要 Yolin 直接說「現在可以跑」才跑，而且一次只跑一場、本 repo 最多 4 個工作程序。**推版前的全套屬於重負載，拿不到許可就不推，不准跳過測試。**
- **刪除**：已 commit 的檔、分支（含兩個備份分支）、Artifact、`.logs/` 裡的證據。
- **花錢、註冊帳號、輸入任何密碼或 token**。
- **正式站資料**：D1／R2 的任何寫入、Worker 部署、`npm run sweep`。
- GitHub 帳號層設定、repo 可見性、改寫**已推送**的歷史。
- **動別的專案**（StockDiary、MealMate、JLPT、查詢島……）的任何檔案——一律唯讀。
- 改 `docs/CONVENTIONS.md`（副本，只有統籌者改主檔）；換自己的模型或 effort。

### 5.4 沒人回應時怎麼辦
- 把要決定的事寫進 STATUS 的「等 Yolin 回覆」：每項列選項、代價、你的建議與理由。
- 轉去做 §5.2 的事；不要因為沒人回就自己拍板使用者看得到的方向，也不要把「等不到許可」變成「跳過那一步」。
- 子代理（投票、勘查）因額度或速率限制失敗：整批改用同一個可用的模型重跑，回報註明，不要停下來問。
- 回報格式照舊：第一行寫結論；繁體中文；分開寫「實測驗證過的」與「推論的」；只跑了部分測試要寫「這不是全套」；結尾寫需要 Yolin 決定的事，沒有就明講沒有。
