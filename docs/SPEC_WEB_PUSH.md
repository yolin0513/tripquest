## 為什麼被提出

目前同步是**輪詢不是推播**：前景每 20 秒問一次，旅伴的動作最慢約 20 秒才出現（見 STATUS.md
「已知限制」）。有人問能不能改用推播，讓「旅伴加入」「有人上傳新照片」這類事件即時通知。

## 客觀事實（PWA 推播的一般性質，非本專案專屬結論）

- **iOS**：Safari／PWA 自 **16.4** 起支援 Web Push，但**必須先「加到主畫面」**，純瀏覽器分頁
  收不到。長輩若沒把 App 加到主畫面，等於沒有。
- **Android**：Chrome 長期支援，門檻低。
- 技術棧：需要 **VAPID 金鑰對** + 前端向使用者**請求通知權限**並拿到 push subscription（endpoint）
  + 後端保存 subscription（可放 D1）+ 後端用 web-push 協議對 endpoint 發送。
- **Cloudflare Worker 可以當發送端**（對 endpoint 送 HTTP），發送量在本專案規模下落在免費額度內。

## 待決問題（要做之前必須回答）

1. **長輩 UX**：權限請求的時機（不能一進 App 就跳）、通知頻率（少而準，否則被關掉或造成焦慮）。
2. **哪些事件值得推**（以下為推論，需 Yolin 定）：旅伴加入、有人上傳新照片、位置分享請求。
   過度通知比不做更糟。
3. **iOS「加到主畫面」門檻**怎麼引導長輩完成，否則 iOS 使用者實際收不到。
4. subscription 生命週期（過期／換裝置／取消授權）怎麼管，避免無效 endpoint 累積。
