# SPEC_測試範圍 修訂二 — 目錄引用不展開閉包，讓放大器 D 恢復作用

> 撰寫：Fable 統籌 Session，2026-09-19。這是 `docs/SPEC_測試範圍.md` 的第二次修訂，另開一個檔是為了不去動你可能正在改的檔。不急，跟下一個工作一起做即可。docs＋`scripts/`，不 bump、不部署。

## 先講結論

修訂一的結果過了驗收：最近十版裡六版少於全套（15～30 支），修訂前是十版全部 44。你回報「放大器 D 仍然不會響」並附了試算，而且修訂 1-B 要求的那條「真實檔」斷言因為前置不成立，你**沒有硬湊**——這正是要的做法。

## 裁決：採用你試算的做法

**一支測試如果引用的是整個目錄（例如 `nearbytest`、`emptytest` 引用 `js/views/`——它們把檔當文字讀，做路由與原始碼稽核，並不執行），這種引用不展開 import 閉包。**

- 改到該目錄底下的任何檔，那支測試照樣被挑中（R3 規則 2 不變）；只是不再沿著那些檔的 `import` 往下算涵蓋。
- 「有沒有人涵蓋」（放大器 D）與 R3 規則 3 都用這個定義。引用單一檔的，照舊展開閉包（但不穿過 `js/app.js`，修訂 1-B）。
- 放大器 D 的模式：你的試算顯示十版裡 D 只觸發 2 版（≤ 3），照修訂 1-B 訂的規則，**維持放大到全套**。

## 要做的事

1. `scripts/affected.mjs`：照上面改。怎麼辨認「目錄引用」由你定（例如引用路徑以 `/` 結尾，或指到的是目錄而不是檔）；辨認規則寫進檔頭註解。
2. `scripts/affectedtest.mjs`，補回修訂 1-B 當初要的那條，現在前置成立了：
   - 前置：「沒有任何測試點名的程式檔」至少 1 個（你試算是 5 個：`expenses.js`、`fx.js`、`photoimg.js`、`places.js`、`viewer.js`；以程式實際算出來的為準，不要寫死 5）。
   - 斷言：改其中一個真實的檔 → 觸發 D、放大到全套、輸出點名那個檔。
   - 對照組：改一個有測試點名的檔 → 不觸發 D。
   - 突變：讓目錄引用重新展開閉包 → 這條紅（因為那些檔又變成「有人涵蓋」）。
3. 重做「最近十版各跑幾支」，新舊並列。預期各版支數不變（你試算過）；**如果變了，回報，不要調規則去湊。**
4. `docs/STATUS.md`「測試範圍」小節：把「仍未解的規則問題」那一段改掉（問題解掉就刪，不要留過期的描述）；新增一行 **「目前沒有任何測試點名的程式檔：N 個」並列出檔名**——這是給 Yolin 看的資訊：這幾個檔改了會自動跑全套，而不是因為有測試守著它們。要不要替它們補測試是另一件事，不在這次範圍，不要順手做。
5. `docs/SPEC_測試範圍.md` 不用改（它的 §11 已標已執行）；只要在 STATUS 那個小節提到本檔即可。

其餘照原規格 §8：每條新斷言手動突變驗紅並寫進回報、push 前公開前自查、回報不准寫全綠、`git push origin main`。
