# 真實地圖（取代甲的示意插畫）：規格（2026-11-05，開發 Session 起草）

建議 effort：medium。狀態：**規格草稿，不寫程式**。地圖顯示方案已投票：**自己寫小的圖磚顯示器（2:1）**，含少數票的守法（單指不吃頁面捲動、按鈕是主路徑、整數縮放、雙指縮放第二版）——見 `docs/VOTE_2026-11-05_地圖顯示.md`。
**CORS 已實測（2026-11-05）**：本機頁面用瀏覽器 `fetch(..., {mode:'cors'})` 取 1 張圖磚 → 200、`type: "cors"`、標頭 `cache-control: max-age=89067, stale-while-revalidate=604800, stale-if-error=604800`。
→ 可以存 CORS 回應（不是 opaque），標頭讀得到。另外：curl 的通用 User-Agent 被擋（回應帶 `x-blocked`、cache-control no-cache），印證條款「通用 UA 會被封」；App 在瀏覽器裡用瀏覽器自己的 UA，沒有這個問題。
Yolin 2026-11-05 已接受離線取捨（看過的才離線看得到、沒看過的退回示意圖並寫明沒網路）。

## 1. 地圖底圖

- 〔轉述〕真實地圖：OSM 點陣圖磚（`https://tile.openstreetmap.org/{z}/{x}/{y}.png`），看得到海岸線、行政界、道路、綠地、地名。
- 〔轉述〕右上角：`＋`、`－`、「回到預設」（房子圖示）三顆鈕。〔我們定的〕每顆至少 44×44，房子鈕旁加字或 `aria-label`「回到整天路線」。
- 〔轉述〕右下角：`© OpenStreetMap contributors`。〔我們定的〕OSM 條款規定必須看得到、不可藏、不可收進開關裡；字級不小於 11px、對比照 palettetest 的標準。
- 〔我們定的〕北朝上、不能旋轉；整數縮放層級、不做慣性。
- 〔我們定的〕手勢（投票的守法）：單指上下滑照樣捲頁面（長輩手指放在地圖上不能卡住）；拖地圖用雙指；第一版縮放只用按鈕，雙指縮放第二版再加。〔轉述沒提到原圖的手勢〕
- 〔我們定的〕一進來的視野＝把當天所有有座標的站框進去（留邊），這就是「回到預設」回去的地方。只有一站時用固定的縮放層級（街區級）。

## 2. 圖釘

- 〔轉述〕每個圖釘是一張**白底小卡**，卡裡一個圖示；右上角一個**粉紅色方塊寫編號**。
- 〔我們定的〕**卡裡放什麼**：v1.74 原則，猜出來的東西不准變成使用者看得到的圖示——**不從名稱猜類型放圖示**（原圖的船、蛋糕、建築，在我們這裡只有「有根據」時才放）。依序：
  1. 那一站有使用者拍的照片 → 最新一張照片的縮圖（甲已寫好的「最新一張投稿」邏輯沿用）；
  2. 對得上內建景點資料庫（`data/places/`）且資料庫有類型 → 那個類型的圖示；
  3. 都沒有 → 卡裡只放大號的編號，不放圖示。
- 〔轉述〕編號＝當天第幾站。〔我們定的〕沒座標的站沒有圖釘，編號照樣跳號（跟時間軸對得上）。
- 〔我們定的〕圖釘的尖端對準座標點；站很近時卡片會疊——v1 不做避讓，被點選的那一站浮到最上層。

## 3. 連線

- 〔轉述〕站與站之間用**粉紅色虛線**依序連起來。
- 〔我們定的〕畫的是**直線**，不是實際道路路線（我們沒有路線資料；畫成沿道路會讓人以為照著走就對）。圖下一行寫明「線是兩站之間的直線，不是實際路線」。
- 〔我們定的〕中間夾著沒座標的站的那一段：淡色細虛線（甲的規則沿用），圖下說明。
- 〔待定〕甲的「1→2 直線約 N km」要不要搬上真實地圖：原圖有沒有，不知道〔轉述沒提到〕。先不放，原圖到了再定。

## 4. 站名標籤列與「整天路線」切換（「依照行程或是全部區分」）

- 〔轉述〕地圖**下面**一排可點的標籤，每個前面一個粉紅編號方塊＋站名（例：`1 JR 札幌 → 南小樽`、`2 小樽住吉神社`…一路到最後一站）。
- 〔轉述〕最前面一顆不一樣的標籤：**黃底、寫「全」＝整天路線**。
- 〔轉述〕底下一行提示，大意是「…地圖看整天路線」。原文不確定，原圖到了照原圖。
- 〔我們定的〕互動：
  - 預設選「全」：視野框住整天、所有圖釘與連線都亮。
  - 點某一站：地圖平移／縮放到那一站（街區級），那一站的圖釘放大並浮到最上層，其他圖釘變淡但留著；標籤列上那一顆變成選中樣式。
  - 再點「全」或地圖上的「回到預設」：回整天。
  - 〔轉述沒說、待核〕原圖的「依照行程」是指**單站**還是**一段（兩站之間）**——例如 `1 JR 札幌 → 南小樽` 看起來像一段移動。原圖到了要核這一條；v1 先做單站。
  - 標籤列可以橫向捲動；目前選中的那顆自動捲進畫面。每顆至少 44px 高。
  - 沒座標的站也出現在標籤列（編號照順序），樣式是虛線框、點了不移動地圖，改在列下寫「這一站沒有位置，地圖上沒畫」——**不默默略過**（Dispatch 對乙的規則，同理適用）。
- 〔我們定的〕這一排是時間軸以外的第二個入口：點標籤**不**捲動頁面、不展開時間軸卡片（避免跳來跳去；長輩容易迷路）。

## 6. 移動圖示與交通方式

- 〔轉述〕Yolin 要移動圖示依「設定的交通工具」變。
- **現況（實查）**：每段交通方式我們**沒有存**——匯入時交通字眼被剝掉（`js/itinerary.js`）、排行程頁的開車／步行切換已移除、「🚆 大眾運輸」查詢結果只在那支手機快取 24 小時、不同步、也不是使用者設定的。
- 〔我們定的〕在資料新增之前：移動圖示用**通用的圓點**，不顯示任何交通工具圖示（不從距離或名稱猜）。
- 要新增時（等 Yolin 回覆＋資料結構投票）：每段一個欄位、使用者自己選（走路／電車／公車／開車／船／飛機／其他）、同步給全家；沒選的段落照樣用圓點。

## 7. 沒網路時（離線退場）

- OSM 條款：**禁止預先下載區域**；**允許**重看時用本機快取的已看過圖磚。
- 〔我們定的〕看過的圖磚由 Service Worker 依快取標頭存（讀不到標頭至少 7 天），**不預載**。實查：`sw.js` 現在對跨網域請求直接放行、不進快取，要另開一個不隨版本刪的圖磚快取（比照 `MUSIC_CACHE`），只收 `tile.openstreetmap.org`、設張數上限、只存 CORS 回應（不存 opaque）。
- 沒網路、需要的圖磚又沒快取到：整張改顯示甲的示意圖（方位照實、不畫底圖），上面一行寫「目前沒有網路，先顯示示意圖；有網路時看過的地方之後沒網路也看得到」。部分圖磚缺：缺的格子留淡色底，不另外說明（推論，待實測看起來怎樣）。
- Yolin 已接受（2026-11-05）。
- 〔我們定的、保守〕快取多舊還能拿出來用：照回應標頭——`max-age`（實測約 1 天）內直接用；過期有網路就重抓；**沒網路時最多用到 `stale-if-error` 給的 7 天**，超過就當沒有、退回示意圖。理由：條款要我們遵守快取標頭，標頭只允許出錯時沿用 7 天。
  代價：出發前超過 7 天看的地圖，到了國外沒網路看不到。要放寬（例如沒網路時不論多舊都拿出來）屬條款解讀，**先問 Yolin，不自己放寬**。
