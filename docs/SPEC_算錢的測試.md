# SPEC_算錢的測試 — 替分帳、匯率、Google 計費守衛補上「驗金額算得對不對」的斷言

> 狀態：已執行（2026-09-21）
> 規劃：Fable 5.1 統籌 Session，2026-09-21。Yolin 2026-09-21 原話：「請一起補測試」。事實依據：你自己 2026-09-21 的唯讀盤點（含實跑 `convert`、`fmtMoney`、`sharePerMember`、`settleTrip` 在 Node 丟 `indexedDB is not defined`）。
> **這一份只補測試與一個純函式的抽出，不改任何金額的算法與畫面。** 盤點找到的缺陷另外處理（§6）。

## 一句話

`js/expenses.js`、`js/fx.js` 現在沒有任何一條斷言在驗金額；`js/places.js` 會花錢的那道守衛（FieldMask 不含 `rating`）與錯誤分支沒人守。補上。**驗收標準是「有斷言在驗金額算得對不對」，不是「改到它們會跑全套」**——現在的全套是因為沒人認領才保守全跑，那不是守護。

## 2. `settleTrip` 怎麼測——統籌者的決定

你列了三條路（puppeteer、裝 `fake-indexeddb`、改程式讓它收一份花費清單），並把第三條標成不在範圍。**統籌者決定走第三條，加一條 puppeteer 的真實入口測試；不加新相依。**

- 把 `settleTrip` 拆成兩層：**純計算的核心**（吃進花費清單、成員、匯率表、基準幣別，回傳每人淨額、轉帳方案、`missingRate` 等旗標；不碰 `store`、不碰 `fetch`、不碰 DOM）＋**薄薄的一層外殼**（從 `store` 讀資料、取匯率，丟給核心）。對外的函式名稱、參數、回傳形狀**完全不變**，呼叫端一行都不用改。
- 這是**等價的抽出，不是改算法**：每一個運算、每一個分支、每一個常數（含 `eps = 0.01`、`total || 1`）原樣搬過去。§6 列的缺陷**這一份不修**——連明顯該修的也不修，免得「補測試」與「改行為」混在一個 commit 裡分不清是誰造成的差異。
- 為什麼不加 `fake-indexeddb`：新相依是你 `CLAUDE.md` 要先問的事，而且測的會是「假的 IndexedDB 上的 `settleTrip`」，不如直接測核心。為什麼不只靠 puppeteer：金額的邊界情況有幾十種，每種走一次瀏覽器太慢，也不好用突變驗。
- 抽出的安全網：先寫 puppeteer 那條真實入口測試（§4 M9）並確認在**抽出之前**是綠的，再抽；抽完同一條仍然綠、畫面上的數字逐字相同。

## 4. 斷言（紀律照舊：每條用突變證明會紅、不寫假斷言、母體非空、對照組；共用慣例 v4 §5）

| # | 斷言 | 前置／對照組 | 突變 |
|---|---|---|---|
| M1 | `convert`：`convert(100,'TWD','JPY',rates)` 等於用同一張 `rates` **手算**的值（手算式寫在測試裡，不要把程式的輸出貼回去當期望值）；同幣別回原值；來回換算（TWD→JPY→TWD）在容許誤差內回到原值 | 前置：測試用的 `rates` 兩個幣別都有 | 把乘除寫反 |
| M2 | `convert`：沒有匯率表 → `null`；未知幣別 → `null`；**不是 0、不是原值、不是 `NaN`** | 對照 M1 | 讓缺值回原值 |
| M3 | `fmtMoney`：TWD 兩位小數含千分位；JPY／KRW／VND／IDR 零小數（四個都驗，清單從 `currencies.json` 讀、不寫死在測試裡）；負數、0、很大的數 | 前置：`currencies.json` 裡零小數的幣別清單非空 | 把零小數的判斷拿掉 |
| M4 | `sharePerMember`：三人均分 100 → 每人 100/3；權重 1:2 分 90 → 30／60；只有部分成員參與 → 沒參與的人不在結果裡 | — | 把權重當成均分 |
| M5 | **守恆（最重要的一條）**：對一組正常的花費（多筆、多幣別但匯率都查得到、不同付款人、不同參與者、不同權重），結清核心回傳的**每人淨額總和為 0**（容許 `eps`）；照轉帳方案執行之後**每個人的淨額都歸零** | 前置：這組資料至少 3 個人、3 筆、2 種幣別 | 讓付款人少記一筆 |
| M6 | `minTransfers`：**只驗語意，不貼死筆數**——轉帳總額守恆、每筆金額 > 0、沒有人同時是付款方與收款方、執行後每人淨額歸零、筆數 ≤ 人數 − 1。它是貪婪法，註解自承是「逼近」最少次數，所以**不准斷言「恰好 N 筆」** | 對照：一組已經兩兩相抵的淨額 → 0 筆 | 讓它漏掉最後一個人 |
| M7 | `getRates` 的快取：12 小時內不重抓、超過就重抓、抓失敗時回舊值並標 `stale`（用假的 `fetch` 與可注入的時間；不准真的打網路——共用慣例 §5.6）| 前置：假 `fetch` 真的被呼叫過／沒被呼叫過的次數 | 讓過期判斷永遠為假 |
| M8 | `places`：假 `fetch` 回 403 → `key`、429 → `quota`、逾時 → `timeout`；**送出的 `X-Goog-FieldMask` 不含 `rating`、`userRatingCount`、`reviews`**，而且只含 `places.js` 宣告的那幾個欄位 | 對照：正常回應照常解析 | 在 FieldMask 加上 `places.rating` → 紅 |
| M9 | 真實入口（puppeteer）：記三筆（不同付款人、其中一筆外幣且匯率查得到）→ 結清頁顯示的每人金額與轉帳方案，等於測試裡**手算**的值；畫面上各人金額加總對得上總花費 | 前置：灌進去的資料真的存進去了、匯率用假的固定值 | 讓畫面顯示的金額與核心回傳的不同源 |
| M10 | 等價抽出的證明：抽出前後，同一組資料經由對外的 `settleTrip` 得到的結果逐欄相同（M9 在抽出前先綠一次，把結果留在回報裡）| — | — |

**`nearbytest.mjs` 那個假斷言一併處理**（你順手抓到的）：約第 76 行的假 Google 端點有 403 模式，但 `placeMode = 'forbidden'` 從沒被設定過——機制寫好了、母體是空的。M8 已經在純 Node 層守住 403；`nearbytest` 那邊二選一：真的設一次並斷言畫面上的錯誤訊息，或把那個沒人用的模式拿掉。不要留著一段看起來有在測、其實從沒跑過的程式。
