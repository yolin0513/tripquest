## 分歧怎麼處理（分歧採保守）

少數票的擔心是真的風險，採 B 時照它的守法一起做：
1. **單指不吃頁面捲動**：地圖區 `touch-action: pan-y`，單指上下滑照樣捲頁面；拖曳地圖改成雙指或按鈕。加一條斷言：單指在地圖上往上滑，頁面 `scrollY` 要變大（代理 2、3 都提）。
2. **按鈕是主路徑**：＋／－、回到預設、站名標籤永遠在、至少 44px；手勢壞了也不卡死。
3. **範圍鎖死**：整數縮放層級、不做慣性、不做旋轉。超出這幾項就重開投票、改用函式庫（代理 1）。
4. **雙指縮放第二版再加**（代理 2 的退路，最保守）；第一版：按鈕縮放＋雙指拖曳。
5. 實機觸控（iPhone、Android 各一台）列為**未實測**，由 Yolin 驗。

## 三票共同指出、跟 A／B 無關的事（實查）

- `sw.js` 現在對跨網域請求**直接放行、不進快取**——看過的圖磚離線時只靠瀏覽器 HTTP 快取、不保證拿得到。要另開一個不隨版本刪的圖磚快取（比照 `MUSIC_CACHE`），只收 `tile.openstreetmap.org`、只存看過的、照 max-age（讀不到 7 天）、設張數上限、**絕不預載**。
- `<img crossorigin="anonymous">` 拿 CORS 回應，不要存 opaque 回應（配額會被灌水、讀不到標頭）。**前提要實測**：OSM 圖磚有沒有回 `Access-Control-Allow-Origin`——沒有的話這條路要改。
- `js/daymap.js` 是等距圓柱投影，接真實圖磚要改成 Web Mercator（或另加一層換算）。
- 沒設 referrer 限制，瀏覽器預設會送來源網域當 Referer，符合 OSM 要求（代理 2 查證；本 Session 先前也查過）。

## 推論、沒驗的（三票都標了）

Leaflet 的大小、是否附 ESM 版、授權版本；OSM 是否送 CORS 標頭；opaque 回應的配額灌水幅度；iOS 手勢行為；自寫 300～500 行的估計。
